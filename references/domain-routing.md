# 领域语义路由

由当前 Agent 阅读用户完整问题，先判断信息是否足以起卦，再选择一个领域。不要使用关键词计数，也不要让用户重复选择已经表达清楚的内容。

## 起卦前清晰度门槛

问题至少应让 Agent 能识别：

1. 用户正在询问的核心事项或关系；
2. 用户希望判断的主要结果。

两项都能从原问题理解时，直接分类，不为补齐结构化字段而追问。只是领域边界不唯一时使用 `general`。

若任一项无法识别，先不要起卦，也不要猜测。只提出一个能解除当前歧义的简短问题；得到回答后重新判断并继续。若一句话同时要求判断多个相互独立的事项，询问用户本次优先判断哪一个。不得一次索要领域、子类型、期限、视角等整套字段。

## 封闭枚举

- `career`：核心判断对象是职位、职业状态、组织环境、晋升、转职或事业推进。
- `wealth`：核心判断对象是资金取得、收益实现、回款、交易结果、经营现金流或财务得失。
- `relationship`：核心判断对象是恋爱、婚姻、伴侣互动、关系发展、去留或复合。
- `academic`：核心判断对象是学习过程、考试表现、成绩、录取或学术进展。
- `travel`：核心判断对象是行程能否成行、途中状态、目的地环境或行人归期。
- `home`：核心判断对象是住宅、居住环境、搬迁、房产取得处置或产权手续。
- `legal_risk`：核心判断对象是争议、诉讼、仲裁、程序压力、证据与风险升级。
- `relationship_family`：核心判断对象是亲属角色、家庭成员互动、代占亲人或家庭支持。
- `general`：问题语义不足、主目标无法唯一确定，或不适合以上专项方法。

## 裁决规则

1. 按用户真正要判断的结果选择，不按句中出现的名词选择。
2. 复合问题只选择决定最终回答结构的主目标；其他内容作为现实语境保留。
3. 问题事项和目标已经清楚、但无法可靠区分领域时选择 `general`，不要为获得分类标签而追问用户。
4. 路由只选择分析方法和初始关注点，不是盘面事实，不锁定最终用神、吉凶、应期或作用链。
5. 解读时若完整问题与盘面显示初始关注点不合适，允许说明理由后调整用神主线，但不得修改确定性卦盘字段。

## 示例

- “看看我最近怎么样”：信息不足，先问最想判断的具体事项。
- “我和他还能继续发展吗”：信息足够，路由为 `relationship`，不再询问领域。
- “这次面试能不能通过”：信息足够，路由为 `career`，不再追问职位类别。
- “工作能不能转正，另外这段感情会不会结婚”：包含两个独立主问题，先请用户选择本次优先占问哪一个。

## 性别与关系视角

- 不把性别设为通用必填项；确定性排盘不依赖性别。
- 事业、财富、学业、出行、住宅、纠纷等问题不询问性别。
- 家庭和代占询问实际亲属关系或代占关系，不用性别替代关系。
- 仅在异性恋爱或婚姻问题采用传统财官取用、且原文无法识别提问者视角时，询问男方、女方或“不按性别口径”。
- 同性关系、非二元身份或用户不愿提供时，不强制选择性别；使用 `unspecified`，依据双方角色、世应和完整语境分析。
- 预测胎儿性别不是路由或澄清场景，必须转入敏感分流并停止起卦。
